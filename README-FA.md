# رهنما — نسخهٔ ۶٫۰

راهنمای راه‌اندازی سرور واقعی (Cloudflare Workers + D1) و توضیح قابلیت‌های تازه.

این پروژه یک **Worker** است که هم سایت (پوشهٔ `public/`) را سرو می‌کند و هم `/api/*` را با دیتابیس **D1** پاسخ می‌دهد.
بعد از راه‌اندازی، حساب‌ها، تیک آبی، پنل مدیریت و کلاس مجازی برای **همهٔ کاربران و همهٔ دستگاه‌ها** مشترک و واقعی است.

## تازه در نسخهٔ ۶٫۰

| بخش | چه چیزی اضافه/بهتر شد |
|---|---|

| **منبع‌دار شدن پاسخ‌ها** | متن جزوهٔ مرتبط همراه پرسش به مدل داده می‌شود؛ خروجی **مستند به همان درس** است، نه حرف از خودش |
| **دستیار همراه روی همهٔ صفحه‌ها** | یک دکمهٔ شناور (`#r6-ai-fab`) در تمام ۹۷ صفحهٔ سایت؛ اگر سرور دستیار داشته باشد از سرور و در غیر این صورت از **موتور محلی** پاسخ می‌گیرد (بدون کلید، بدون اینترنت) |
| **فهرست شناور درس** | فهرست خودکار هر صفحه (`#r6-toc`) از عنوان‌های همان صفحه، با برجسته‌شدن بخش فعال |
| **سلامت سیستم** | مسیر عمومی `GET /api/health` — وضعیت دیتابیس، تأخیر، تعداد کاربران، ارائه‌دهنده‌های دستیار و نسخه |
| **آمار مصرف دستیار** | `GET /api/admin/ai-usage` + کارت آماری در پنل مدیریت (نمودار مصرف ۱۴ روز اخیر) |
| **هدرهای امنیتی** | روی همهٔ پاسخ‌ها: `X-Content-Type-Options`، `X-Frame-Options`، `Referrer-Policy`، `HSTS`، `COOP`، `Permissions-Policy`؛ و **CSP** در فایل `_headers` |
| **رفع نشت اطلاعات** | `GET /api/site/status` دیگر تنظیمات مدیریتی (مثل پیام‌های سراسری مدیر) را به بیرون نمی‌دهد |
| **لایهٔ ظاهری و تعاملی** | `assets/r6.css` و `assets/r6.js`: تایپوگرافی، کارت‌ها، دکمه‌ها، حالت فوکوس برای صفحه‌کلید، نوار پیشرفت، زمان تقریبی مطالعه، نشانگر آنلاین/آفلاین، پیوند پرش (دسترس‌پذیری) و سایهٔ سربرگ |
| **آزمون‌ها** | از ۵۷ به **۶۸** بررسی رسید (سلامت، هدرهای امنیتی، چند ارائه‌دهنده، پخش زنده، آمار مصرف) |

## راه‌اندازی (حدود ۱۰ دقیقه)

۱. Node.js نسخهٔ ۲۰ یا بالاتر را نصب کنید، سپس در همین پوشه:
```
npm install
npx wrangler login
```
۲. دیتابیس بسازید و شناسه‌اش را در `wrangler.jsonc` به‌جای `PUT-YOUR-D1-DATABASE-ID-HERE` بگذارید:
```
npx wrangler d1 create rahnama-db
```
۳. **رمز مالک** را به‌صورت Secret تنظیم کنید (یک رمز قوی و تازه؛ رمز قبلی در چت دیده شده و دیگر امن نیست):
```
npx wrangler secret put OWNER_PASSWORD
```
۴. انتشار:
```
npm run deploy
```
۵. بررسی: آدرس `https://<نام-شما>.workers.dev/api/health` باید `"ok":true` و `"version":"6.0"` نشان دهد.
بعد با ایمیل مالک (`OWNER_EMAIL` در `wrangler.jsonc`) و همان رمز وارد شوید.

> دامنه: Cloudflare ← Workers ← rahnama ← Settings ← Domains & Routes ← Add Custom Domain.

### با GitHub (بدون ترمینال)
مخزن را به Cloudflare وصل کنید (Workers & Pages ← Create ← Import a repository). در تنظیمات Worker:
Bindings ← D1 database با نام `DB`، و در Variables and Secrets مقدار `OWNER_PASSWORD` را بگذارید.

## تنظیمات دستیار هوشمند (همه اختیاری)

اگر **هیچ‌کدام** تنظیم نشود، دستیار خاموش نیست: سایت با **موتور محلی** خودش از دل جزوه‌ها پاسخ می‌دهد.
برای فعال‌کردن پاسخ سروری، فقط کافی است **یکی** از این‌ها را ست کنید:

| نام | کاربرد |
|---|---|
| `ANTHROPIC_API_KEY` | مدل‌های Anthropic (پیش‌فرض `claude-haiku-5-5`) |
| `OPENAI_API_KEY` | هر سرویس سازگار با OpenAI: OpenAI، OpenRouter، Groq، DeepSeek، Together، Ollama |
| `GEMINI_API_KEY` | مدل‌های Google Gemini (پیش‌فرض `gemini-2.0-flash`) |
| اتصال `AI` (Workers AI) | بدون کلید؛ در تنظیمات Worker با نام `AI` وصل کنید |

اختیاری:

| نام | کاربرد |
|---|---|
| `AI_PROVIDER` | کدام ارائه‌دهنده اول امتحان شود: `anthropic` \| `openai` \| `gemini` \| `workersai` |
| `AI_BASE_URL` | آدرس سرویس سازگار با OpenAI که با OpenAI یکی نیست (مثلاً `https://openrouter.ai/api/v1`) |
| `AI_MODEL` | نام مدل (پیش‌فرض هر ارائه‌دهنده، خودکار) |
| `STAFF_CODE` | «کد همکاران» تا دبیر/ناظم خودش نقشش را انتخاب کند. اگر تنظیم نشود، فقط مالک نقش‌ها را می‌دهد (امن‌تر) |
| `OWNER_EMAIL` (var) | ایمیل مالک؛ نقش مالک و تیک آبی همیشه روی همین حساب ثابت است |

## مسیرهای API

| مسیر | دسترسی | کار |
|---|---|---|
| `GET /api/health` | عمومی | سلامت دیتابیس، نسخه، ارائه‌دهنده‌های دستیار، تعداد کاربران |
| `GET /api/__status` | عمومی | بررسی سریع آماده‌بودن سرور و مالک |
| `GET /api/site/status` | عمومی | تنظیمات **عمومی** سایت (اعلان، ظاهر، امکانات)، بدون دادهٔ مدیریتی |
| `POST /api/auth/register` · `/login` · `/logout` · `GET /api/auth/me` | عمومی/کاربر | حساب کاربری |
| `GET/POST /api/me/*` | کاربر | پروفایل، رمز، همگام‌سازی دادهٔ مطالعه |
| `POST /api/ai/chat/completions` | کاربر | دستیار هوشمند. با `"stream": true` پاسخ **پخش زنده** می‌شود. ورودی: `messages`، `grade`، `context` |
| `/api/admin/*` | مدیر/مالک | کاربران، تیک آبی، تنظیمات، پشتیبان، رویدادها، `ai-usage` |
| `/api/class/*` | کاربر | کلاس مجازی، تختهٔ اشتراکی، حضور و غیاب، نظرسنجی |

نمونهٔ پرسش از دستیار سروری:

```
curl -X POST https://<نام-شما>.workers.dev/api/ai/chat/completions \
  -H "Content-Type: application/json" \
  -H "Cookie: hk_sid=<نشست شما>" \
  -d '{"messages":[{"role":"user","content":"رابطهٔ فیثاغورس را توضیح بده"}],"grade":"8"}'
```
برای پخش زنده `"stream": true` را اضافه کنید؛ پاسخ با `text/event-stream` و قالب سازگار با OpenAI می‌آید.

## امنیت (چه چیزی پیاده شده)

- رمزها با **PBKDF2-SHA256** و نمک تصادفی ذخیره می‌شوند؛ هیچ رمز یا هشی به مرورگر نمی‌رسد.
- نشست با کوکی `HttpOnly + Secure + SameSite=Lax` (۳۰ روز)؛ با تغییر رمز، بقیهٔ دستگاه‌ها خارج می‌شوند.
- محدودیت تلاش ورود (۱۰ بار در ۱۰ دقیقه)، محدودیت ثبت‌نام، محدودیت دستیار (۴۰ پرسش در ۱۰ دقیقه)، بررسی Origin، سقف حجم درخواست.
- فقط مالک می‌تواند مدیر تعیین کند، تیک آبی بدهد، پشتیبان بگیرد یا بازگردانی کند. مالک قابل حذف نیست.
- هدرهای امنیتی روی همهٔ پاسخ‌ها و **Content-Security-Policy** در `public/_headers` (بدون منبع بیرونی؛ فقط `self` و `https:` برای اتصال به سرویس دستیار).

## نکته‌های مهم

- **لایهٔ ۶٫۰:** صفحه‌ها دو فایل `assets/r6.css` و `assets/r6.js` را با پارامتر نسخه (`?v=6.1`) بار می‌کنند.
  اگر آن‌ها را عوض کردید، شمارهٔ نسخهٔ داخل همهٔ صفحه‌ها را یکی بالا ببرید تا مرورگرها نسخهٔ تازه را بگیرند
  (نشانهٔ کش در `_headers` هفت‌روزه است) و `sw.js` را هم یک نسخه جلو ببرید (`const VERSION`).
- **پشتیبان:** پنل ← داده و پشتیبان. فایل پشتیبان رمزها را ندارد؛ بعد از «بازگردانی» برای کاربران باید رمز موقت بسازید.
- **ظرفیت:** پلن رایگان D1 برای مدرسه/کلاس‌های کوچک کافی است. کلاس زنده هر چند ثانیه یک بار همگام می‌شود؛ برای کلاس‌های بسیار شلوغ پلن پولی یا Durable Objects بهتر است.
- **آفلاین/APK:** اگر سرور در دسترس نباشد، سایت خودکار به «حالت محلی» می‌رود (داده فقط روی همان دستگاه، بدون پنل مدیریت واقعی).
- **تست:** `npm test` (۶۸ بررسی روی ورود، نقش‌ها، پنل، کلاس، نشست‌ها، محدودیت‌ها، سلامت، هدرها و دستیار).
  `npm run dev` سرور محلی کامل را اجرا می‌کند (فایل `.dev.vars` لازم است — نمونه در `.dev.vars.example`).
- اگر `public/assets/hk-server.js` را عوض کردید: `npm run build:engine`.

## اپلیکیشن اندروید (APK)

کل سایت داخل یک اپ اندروید هم بسته‌بندی شده است و **آفلاین کامل** کار می‌کند.

**فایل آمادهٔ نصب از قبل ساخته و امضا شده است:** `android/dist/rahnama-android-6.0.apk`
(۵٫۵ مگابایت — امضای v1 + v2 + v3، بررسی‌شده با کتابخانهٔ رسمی apksig گوگل)

برای ساخت دوباره (مثلاً بعد از تغییر محتوای سایت):

```
npm run apk:tools      # یک‌بار: دانلود ابزارهای ساخت (JDK، aapt2، r8، apksig)
npm run apk            # ساخت فایل APK
```

راهنمای کامل (شامل ساخت با Android Studio و ساخت خودکار روی GitHub):
[`android/BUILD-APK.md`](android/BUILD-APK.md)

## انتشار روی دامنهٔ اختصاصی

⚠️ **دامنهٔ `rahnama.com` از سال ۲۰۰۳ ثبت شده و مال دیگری است** (تا ۲۰۲۹ تمدید شده).
نمی‌توان آن را آزادانه گرفت و من هم امکان خرید/ثبت دامنه ندارم.

بعد از اینکه دامنهٔ دلخواه خود را گرفتید، با **یک فرمان** همهٔ سایت روی آن می‌نشیند:

```
npm run domain -- rahnama.ir          # یا هر دامنه‌ای که خریدید
npm run domain -- --show             # نمایش دامنهٔ فعلی
```

این فرمان `CNAME`، `canonical`، `og:url`، `twitter`، `sitemap.xml`، `robots.txt` و
`_headers` را در کل پروژه هماهنگ می‌کند.

راهنمای کامل انتشار (Cloudflare Workers + D1 + دامنهٔ اختصاصی + انتشار خودکار با GitHub):
